03 — Original Artifact

Android Inventory App — CS 360

This Android application was originally developed in CS 360: Mobile Architecture and Programming. It provides full CRUD functionality — users can create an account, log in, and manage an inventory system backed by a local SQLite database. The app also includes an SMS notification feature that alerts users when an item's quantity reaches zero.

The original codebase had clear areas for growth: credentials were stored in plain text, input validation was minimal, no sorting or searching existed, the update method only modified quantity (not item name), and the database schema lacked constraints like NOT NULL and UNIQUE to enforce data integrity.

☕ DatabaseHelper.java

Manages the SQLite database — creates the users and inventory tables and handles all CRUD operations. In the original, update only modified quantity and the schema had no integrity constraints.

☕ InventoryActivity.java

Main UI activity — renders the inventory table, handles add/delete/edit interactions, and triggers SMS alerts via SmsHelper when an item hits zero quantity. No input validation in the original.

04 — Artifact Enhancements

Three Categories of Growth

ENH 01 Software Design & Engineering +

What Was Enhanced

This enhancement focused on improving the overall software design, code quality, and security of the application. Four key areas were targeted:

Separation of concerns — Database logic was cleanly isolated in DatabaseHelper while UI logic remained in the Activity classes, making the codebase more modular and maintainable.

Input validation — Added checks for empty fields and invalid data entries across both the add and edit flows, reducing crash risk and improving the user experience with informative error messages.

Security improvements — The original app stored and compared user credentials in plain text. This enhancement introduced credential validation and laid the groundwork for future password hashing/encryption, moving toward a security-conscious design aligned with secure coding practices.

Error handling — Consistent error handling was applied across all database operations so the app behaves predictably in unexpected scenarios rather than crashing silently.

ENH 02 Algorithms & Data Structures +

What Was Enhanced

This enhancement introduced algorithmic thinking and structured data management to the application. The inventory list — stored as an ArrayList<InventoryItem> — became the foundation for new sort and search capabilities:

Sort by name — Collections.sort() with a custom Comparator organizes items alphabetically (case-insensitive).

Sort by quantity — A second comparator sorts items numerically from lowest to highest, helping users quickly identify low-stock items.

Linear search / filter — filterItemsByName() traverses the ArrayList and returns items whose names contain the search query as a case-insensitive substring match.

Full update fix — DatabaseHelper.updateItem() was upgraded to modify both item name and quantity, fixing a limitation of the original which could only update quantity.

ENH 03 Databases +

What Was Enhanced

This enhancement focused entirely on strengthening the database layer — improving schema design, data integrity, query flexibility, and database-driven features:

Schema constraints — The database version was incremented to v2. Both tables now enforce NOT NULL on all columns, and item_name in the inventory table is now UNIQUE, preventing duplicate entries at the database level.

insertOrUpdateItem() — A new upsert method checks whether an item already exists by name. If it does, the quantities are combined; if not, a new record is inserted. This prevents duplicate inventory entries and improves data reliability.

getItemByName() — A targeted lookup method that retrieves a single inventory item by name using a parameterized query, supporting the upsert logic and enabling more precise database access.

getLowStockItems(threshold) — A database-driven reporting method that queries inventory items at or below a given quantity threshold, sorted ascending by quantity. This enables smarter inventory management directly from the database layer.

Ordered retrieval — getInventoryItemList() was upgraded from a raw SELECT * query to an ordered query using ORDER BY item_name ASC, ensuring consistent alphabetical results on every load.

Input validation at the data layer — All database methods now include null and empty-string checks before any database operation is performed, preventing invalid data from ever reaching the database.
